## 一、全局设计总纲与参考基线对齐（8 张截图 × AnimalTrip × EggBabe 双端现状）

### 1.1 核心设计哲学：借「场景拟物容器」之形，铸「EggBabe 冷幽默陪伴与潮玩质感」之魂

通过对 `animaltrip.qiaoqiao.social`（动物去哪儿）前端全量 Bundle、多房间状态机与 8 张截图中交互细节的拆解，我们可以提炼出它最打动人心的设计长板——**「去工具化 HUD，把系统功能藏进房间里可触摸的家具与小摆件中」**：时间不再是冷冰冰的顶栏悬浮字，而是一只可以翻过来看背面的青蛙小座钟；日记、相册、明信片不再是零散的底部按钮，而是落地木书架上点击会飞出来的布面手帐本；旅途带回的小物件则被安放在温润的原木多宝格与小院信箱里。

但与此同时，`animaltrip` 在实机落地上也暴露出**三大明显短板**，恰恰是 EggBabe 可以精准超越、做出差异化品质感的关键机会：

| 对比维度 | `animaltrip`（动物去哪儿）现状与短板 | EggBabe 升级策略与超越点 |
| :--- | :--- | :--- |
| **1. 翻转闹钟背面体验** | 截图六（`image_6.png`）翻到背面后，`back-v2.webp` / `frog-clock.glb` 上的 **3 颗一字螺丝、2 枚黄铜旋钮与电池盖完全是死贴图**，点击无任何反馈、无计时或作息功能，玩家翻看一次便失去把玩动力。 | **背面真可玩化**：保留 180° 丝滑翻转惊喜，将背面升级为**可拧动黄铜专注发条（伴随棘轮咔哒声效，完成 15/25 分钟陪伴专注赚取 `✦` 星星并写入当晚日记）+ 昼昏夜作息轻提醒小拨盘 + 滴答白噪音机械拨杆**。 |
| **2. 木质收藏柜交互深度** | 截图八（`image_8.png`）上半部精美的 `3×4` 原木博古架（`collection-cabinet-handdrawn-v4-960.webp`）**仅是一张写死的静态装饰横幅插画**，玩家真正解锁的藏品只能显示在下方扁平白底卡片或散放在地板上，无法摆进木格里。 | **真·可交互多宝格 + 房间书架联动**：将 `3×4`（12 格）暖橡木多宝格做成真正的**实时交互陈列容器**，支持从 `eggbabe-miniprogram` 现成 **41 件 3D 透明小物件**中自选 12 件入柜摆拍，且前排展品**实时微缩映射至起居室「原木书架」**。 |
| **3. 跨端性能与资源兼容** | 重度依赖 `.webp` 资源与高达 **`42,242` 顶点**的 Three.js `frog-clock.glb` 模型，在部分 iOS 微信客户端、小程序 WebGL `createImage()` 与中低端机型上存在解码兼容隐患与首屏包体压力。 | **严守 `AGENTS.md` 全端原生兼容规范**：**100% 采用 `pngquant --quality=80-95 --speed=3 --strip` 压缩 RGBA PNG（严禁任何 `.webp`）**，翻转钟采用正/背面高精度 PNG + 动态指针 + CSS 3D `perspective` / `rotateY(180deg)` 厚度投影，H5 与微信小程序/小游戏双端零兼容风险满帧 60fps；角色与衍生形象深度融合 **锦鲤（12 套）+ 玉兔（24 套，露双长耳、严禁粉色腮红）** 独家潮玩基因与零 Token 换装拍立得。 |

## 二、模块一：左上角 HUD 状态牌精简重构与「个人信息 & 宠物档案」弹窗（对应需求 1、1a、1b）

### 2.1 左上角状态牌精简重设计（精准落地 1a & 1b）

#### （1）现状代码级痛点诊断
在当前 `eggbabe-h5`（对应**截图二 `image_2.png`**）中，左上角 `#pet-mood-tab`（`index.html:64–101`）存在三处明显的体验与实现缺陷：
1. **纵向冗余与硬编码未持久化 Bug（对应 1a）**：`index.html:80` 单独占用了整整一行 `<span id="hud-companion-days" class="pet-mood-tab__days">连续一起 12 天</span>`，且在 `living-room-dress/app.js:297` 中 `companionDays: 12` **被硬编码写死为 `12`**，在 `persistState()`（`app.js:323–337`）中完全漏存，既无 `firstMetAt` 初次相遇时间戳，也无每日有效互动打卡结算。与此同时，首行右侧的浅鼠尾草绿胶囊 `#hud-lv-pill`（`index.html:78`，`style.css:1660–1668`）仅静态显示低频的 `Lv.1`。
2. **饱食度与清洁度首屏被折叠隐藏 Bug（对应 1b）**：`index.html:98` 的 `#hud-care-mini`（`饱食 X% · 清洁 Y%`）被塞进了 `#mood-room-sentence` 内部。由于 `app.js:293` 默认 `state.moodPhase = "summary"`，而 `style.css:385–395` 规定 `.pet-mood-tab__room-sentence` 在非 `"expanded"` 态下 `max-height: 0; opacity: 0; overflow: hidden`，导致**玩家首次进入房间时完全看不见饱食度与清洁度**，必须盲点一次卡片才能展开看到 `8.5px` 的灰字。
3. **点击行为单调且与隐藏调试手势耦合**：当前点击 `#pet-mood-tab`（`app.js:677–692`）仅在 `minimal / summary / expanded` 三态间循环折叠，无法查看完整账号与双宠档案；且 `2400ms` 内连点 5 次会呼出右上角 `#dev-testers` 验收工具，若直接改为点击开弹窗会产生手势冲突。

#### （2）精确改造清单（零模糊点）

## 四、模块三：宠物日记的精髓、DeepSeek 反废话生成架构与场景「原木书架」中枢（对应需求 3，参考截图七）

### 4.1 深度讨论：宠物日记的「精髓」是什么？如何彻底消灭 AI 废话空话？

#### （1）为什么绝大多数“AI 宠物日记”不好看？（现状与反面教材剖析）
目前 `eggbabe-h5` 的 `#today-companion-overlay`（`app.js:601–634`）只是把 `${bg.name}` 塞进固定模板（如*“今天去『晚霞云朵坡』散步啦，长耳朵听见了很温柔的风声…”*），没有时间轴归档，也完全不知道玩家今天对它做了什么。

而如果只是简单把大模型接进来写“每日宠物日记”，90% 的 AI 会立刻滑向以下**三大“废话空话重灾区”**：
1. **成人贺卡鸡汤腔**：*“亲爱的主人，今天又是元气满满的一天！阳光洒在窗台特别温暖治愈，谢谢你一直以来的陪伴，明天也要继续加油鸭！！！”* —— 充满宏大抽象形容词（温暖、治愈、美好、岁月），毫无画面感。
2. **爹味叮嘱客服腔**：*“天冷了记得多穿衣服多喝热水哦，不要熬夜，我会一直守护你的～”* —— 像群发养生短信，完全不像一只住在木屋桌角的小生灵。
3. **凭空捏造假日常**：玩家明明今天给它穿了「宇航员套装」、喂了「香酥小鱼干」，AI 却瞎编“今天去草地追了一下午蝴蝶”，瞬间打破陪伴信任感。

#### （2）EggBabe 宠物日记让人百读不厌的「三大核心精髓」

结合 `eggbabe-miniprogram` 已经验证成功的叙事圣经（`docs/设计素材/参考资料/02_IAA陪伴_早期日常系统结构_v0.3.md` §6.3 的 7 条硬约束与 §6.3.1 四大冷幽默结构），真正的神级小宠物日记必须抓住以下三大精髓：

1. **精髓一：真实交互记忆锚点（「原来我随手做的小事，它都偷偷记在心里了」）**
   - 每篇日记必须精准咬住**当天真实发生过的 1–2 个具体玩家行为或房间事实**（从前端 `dailyEventLog` 提取）：
     - 你喂给它的具体零食名（如「桂花蜜糕」掉了一颗碎渣在桌上）；
     - 你给它换上的具体衣服名（如穿「夏日祭浴衣」怕踩到下摆，走路变成小碎步）；
     - 你今天帮它搓了泡泡澡，还是忙忘了让它清洁度掉到 `<30`（它不好意思直说，只写*“今天路过小木镜的时候绕着走了一圈”*）；
     - 你拧了床头小青蛙表 25 分钟发条，或带它在「一起画」里画了一只歪歪的小黄鸭。

2. **精髓二：幼态微感官与物象叙事（只写五感小细节，绝不拔高讲道理）**
   - 严格贯彻小程序 PRD §6.3 铁律：**只写触觉、声音、温度、光斑、边角等具体小物件**（袖口线头、咖啡杯热气、卷笔刀木屑、雨滴敲荷叶），正文统一控制在 **2–3 个短句、`60–105` 个汉字（护栏宽容校验区间 `50–125` 字）**，另附一句 **`20` 字以内的 `P.S.` 小注脚**（8 秒读完，意犹未尽），结尾永远落在**一个憨态可掬的小动作或小习惯**上，绝不升华主题、绝不喊口号。

3. **精髓三：植入小程序 PRD §6.3.1「四大冷幽默反转结构」（反废话的灵魂武器！）**
   - 为什么 `eggbabe-miniprogram` 里的 39 篇纪念物故事读起来高级又好笑？因为它们严格套用了 **4 种克制的冷幽默逻辑错位**。我们将这 4 种结构直接作为每日日记生成的轮换叙事骨架：
     - **结构 ①「重新定义失败」（Redefine Failure）**：诚实承认一件事没做成，但一本正经地换一套对自己有利的评判标准。
     - **结构 ②「明知故犯」（Knowingly Persist）**：明明知道某件事为什么行不通/有小毛病，偏偏觉得这样挺好、坚决不改。
     - **结构 ③「位置的反讽」（Positional Irony）**：正因为穿了某件衣服或待在某个地方，反而产生可爱的反差窘境。
     - **结构 ④「数量的错位」（Disproportionate Numbers）**：为了一件芝麻大的小事，极其认真地重复了很夸张的次数或时长。

#### （3）直观效果验证：同一天的相同互动，废话 AI vs EggBabe 双宠冷幽默日记对比

### 4.2 什么时候生成？怎么生成？（DeepSeek API 安全代理与混合流水线）

#### （1）生成时机：「有真实互动才日结 + 懒加载触发 + 缺席绝不补发」
1. **每日正篇上限 1 篇，按宠分槽懒加载结算（省 Token、零串味）**：
   - 前端通过 P0 底座按 **`dailyEventLog[dateKey][petId]` 双层键**记录双宠各自当日互动快照（喂过的零食、是否搓澡、穿过的 `catalog.json` 合法套装 ID、点亮过的 5h 状态、专注发条时长、小游戏与新获小物件，最多保留最近 14 天滚动窗口），同一天切换锦鲤⇄玉兔绝不相互覆盖；晚间结算自动选取当日互动频次更高的一只主写（另一只可作为室友彩蛋轻提一句）。
   - **触发时刻**：
     - **当晚主动翻阅**：本地时间 **`21:00` 之后**，若当日 `dailyEventLog[dateKey]` 至少有 `≥1` 项真实互动，玩家点开书架上的《陪伴日记本》时，实时生成并落盘今日日记（伴随钢笔沙沙写字微动效，约 `1.2s` 出字）；
     - **次日首访补结**：若昨晚未点开日记本，次日玩家首次进入房间时，静默为**最近一个有真实互动的历史日**补结 1 篇日记，并在书架日记本上挂起一枚暖黄色小书签提醒（无红点焦虑）。

#### 老存档无损迁移契约（`migrateFromLegacyV4(v4, careV1)`）与存储配额防爆红线
1. **字段级零丢失映射（`eggbabe_living_room_mp_v4` + `eggbabe_care_v1` → `eggbabe-cross-end-v1`）**：
   - `v4.petId` → `activePetId`；`v4.stars` → `companion.starBalance`；`v4.sfxOn` & `v4.stageBgId` → `settings.{sfxOn, stageBgId}`；`v4.unreadMail === false` → 标记今日 `companion.dailyLetterClaimedDate`；
   - `v4.savedSet.{koi, yutu}` → 经 `catalog.pets[petId].items` 合法性校验后写入 `pets.{koi, yutu}.equippedSetId`（若旧值缺失或跨宠异常则回退默认套装 `"set_duck"` / `"set_cozy_knit"`）；`careV1.{koi, yutu}` → `pets.{koi, yutu}.care`；
   - `v4.keepsakes[]`（及小程序导入存档 `eggbabe_post_hatch_v36`）→ 经 `keepsakeAliasNormalizer` 转换：命中 41 件已渲染目录的写入 `curioCabinet.unlockedIds` 并自动填充前排空 `shelfSlots`；命中暂未渲染叙事 ID（如 `sun-speck`、`bread-ticket`）的无损存入 `curioCabinet.deferredUnlockedIds`（严禁像旧版 `app.js:316` 那样静默 `.filter()` 丢弃）；
   - `v4.postcards[]` → 提取 `{ id, petId, outfitId, sceneId, text, createdAt }` 配方元数据写入 `postcards[]`（若历史记录含内联 `data:image/...;base64` 字符串，迁移时自动剥离重型像素串，仅保留合成配方）。
2. **`5MB–10MB` 存储配额防爆铁律（严禁持久化 Base64 DataURL）**：
   - `localStorage`（通常上限 `5MB`）与微信小程序 `wx.setStorageSync`（单 Key 上限 `1MB`、总上限 `10MB`）中，`diaries[]`、`postcards[]` 与 `lookbookPhotos[]` **严禁存储任何 base64 PNG/JPEG DataURL**，一律只持久化 **`~300 Bytes / 条` 的纯文本合成配方元数据**（千篇日记仅占 `~300 KB`）；
   - `800×920` 拍立得画幅在打开内页时调用 `composeCleanIllustrationUrl(petId, outfitId, sceneId)` 实时合成或将二进制缓存于 `IndexedDB` / `wx.env.USER_DATA_PATH`；`dailyEventLog` 每次写入自动裁剪超过 **14 天** 的历史原始日志；存储异常捕获时主动弹出温和清理提示而非静默吞错。
